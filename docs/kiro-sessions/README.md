# Kiro build sessions

The team wrote the spec (`.kiro/specs/carbon-copy/`), the steering files and the hooks; the Kiro CLI (`kiro-cli chat --no-interactive --trust-all-tools`) implemented every task from them, one run per task, and Kiro kept the spec current as it went (each time a gap was found, the requirement was written first, then the code). The custom agent `carbon-attacker` was run four times against the build (records 10, 12, 16 and 17, and 23); the third run was stopped by a network error before its report and resumed once, so records 16 and 17 are one run. Each run found: **first run (10), six:** five ways to hide a change or raise a false alarm and one documented limit of the cleaning, and it reported that its own MCP tools did not load (task 11 fixed them); **second run (12), seven:** the download the command line could not read, a traceback, a screen saying "went to PayPal" when PayPal refused, three disagreements between the browser and Python, a run header the seal did not cover, the device forgetting old runs, and a stale copy read against a newer stamp (task 12); **third run (16 and 17), thirteen:** F1 to F13, among them a payout through MCP that left no carbon copy, a tap that errored and left no receipt, and a payout of NaN dollars (tasks 15 to 18); **fourth run (23), twelve:** the owner's tap could pay a bill twice, a forged `X-Forwarded-For` or a made-up cookie got round the limits, a read-only MCP tool grew the book past its cap, a waiting payment could be forgotten, `verify.html` called a forged book intact, and a payout of 0 was allowed (task 21). A few things were done by hand, each in a commit whose message does not say "built by Kiro": the first spec, the steering files and the hooks (`92e8580`), the package list (`requirements.txt`), the hosting recipe (`Dockerfile`, `render.yaml`), the README's demo link, run commands, category line and pictures, the key scanner's skip list (`tools/no_keys.py`), and these session records. Each file here is one Kiro run: the instructions exactly as given, then the steps Kiro narrated as it worked and its own end report, copied from the run's log with only personal folder paths removed. Tool-call progress lines are left out. Between runs a person checked the result (the tests, the attacker's reproductions, a click-through in the running app) and committed it; the commit messages say which commit each run became.
